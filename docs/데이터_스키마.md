# 장면 데이터 스키마

대사·선택지·조건은 전부 `data/*.json`에 있다. `src/engine.js`는 이 구조를 해석만 하고, 규칙을 코드 안에 새로 만들지 않는다. 대본이 바뀌면 JSON만 고친다.

---

## 1. 파일 하나 = 구간 하나

```json
{
  "segment": "S1",
  "title": "선곡",
  "background": "bg01-classroom-day.jpg",
  "start": "P-01",
  "nodes": { "P-01": { ... }, "S1-01": { ... } }
}
```

---

## 2. 줄(line)

화면에 순서대로 나오는 한 단위다. `kind`로 구분한다.

| kind | 뜻 | 필드 |
| --- | --- | --- |
| `say` | 인물의 대사 | `who`, `text` |
| `narrate` | 장면 서술·행동 묘사 | `text` |
| `note` | 게임 안내(진입 안내 등) | `text` |
| `place` | 장소·시간 표지 | `text` |
| `card` | 엔딩의 돌아보기 카드 | `title`, `text` |
| `recall` | 실제 선택과 그때의 해슬 반응 재현 | `choiceIds` 또는 `choicePrefix`, 다음 마디에서 반응한 경우 `fallbackReactions` |
| `reflection` | 성찰 질문·마무리 활동 | `text` |
| `retryComparison` | 첫 선택과 재도전의 말·반응·결과 비교 | `resultLabels` |
| `oneOf` | 조건에 맞는 **첫 묶음 하나만** 보여 준다 | `cases: [{ "when": ..., "lines": [...] }]` |

모든 줄에 `when`을 붙일 수 있다. 조건이 거짓이면 그 줄을 건너뛴다.

`oneOf`는 회복 지점의 진입 대사처럼 **우선순위가 있는 분기**에 쓴다. 배열 순서가 곧 우선순위이고, 여러 조건이 겹쳐도 위의 것 하나만 나온다.

---

## 3. 마디(node)

### `scene` — 대사만 있고 선택이 없는 장면

```json
{ "type": "scene", "place": "2학년 개학 날, 교실",
  "lines": [ ... ], "next": "S1-01" }
```

### `choice` — 선택 지점

```json
{ "type": "choice", "lines": [ ... ],
  "display": ["D", "C", "A", "B"],
  "options": { "A": { ... } } }
```

`display`는 **화면에 보이는 순서**이고 `options`의 키는 대본의 선택 ID다. 둘을 분리해 둔 이유는 부적절한 선택의 화면 위치를 지점마다 다르게 두기 위해서다. **구현에서 이 순서를 섞지 않는다.**

### `record` — 구간 종료와 기록

```json
{ "type": "record", "lines": [ ... ],
  "outcome": [ { "when": ..., "set": { "S1": "해결" } } ],
  "next": "S2-01" }
```

### `end` — 최종 학습 내용 정리

`REVIEW-SUMMARY`는 화면 코드가 기존의 개인별 해설 카드(`REVIEW-LAST`·`REVIEW-EARLIER`·`REVIEW-BALANCE`)와 자신의 공통 학습 내용·성찰 질문을 한 화면에 모아 그린다. 이때 기존 카드의 조건과 대표 장면 선택 우선순위는 그대로 읽는다. 재도전 메뉴는 최종 화면에 표시하지 않는다.

### `menu` — 이전 재도전용 메뉴(현재 최종 흐름에서는 사용하지 않음)

```json
{ "type": "menu", "lines": [ ... ],
  "actions": [
    { "text": "같은 장면에서 다르게 말해 보기", "action": "retry" },
    { "text": "오늘의 대화 정리하기", "action": "finish" }
  ] }
```

## 4. 선택지(option)

```json
"A": {
  "gesture": "해슬 쪽으로 몸을 돌린다",
  "text": "왜 그 곡 하고 싶은지 더 얘기해 줄래?",
  "appropriate": true,
  "area": "empathy",
  "method": ["공1", "공3"],
  "response": [ ... ],
  "set": { "stageMemory": "full" },
  "flags": ["recovery:S1-01-C"],
  "next": "S1-02"
}
```

| 필드 | 뜻 |
| --- | --- |
| `gesture` | 비언어 지문. **모든 선택지에 반드시 있어야 한다.** 하나만 빠지면 그것이 정답 표식이 된다 |
| `text` | 학생이 고르는 말. 대본 원문 그대로 |
| `appropriate` | 적절/부적절. 선택 전에는 노출하지 않는다. 부적절한 선택 뒤 표지와 영역 집계에 쓴다 |
| `feedback` | 부적절한 선택에만 넣는 한 문장 근거. 인물의 `response`를 모두 보여 준 뒤 대화 신호로 표시한다 |
| `area` | `empathy` / `mediation` / `null`(부적절). 영역 집계의 근거 |
| `method` | 교과서 방법 약칭. 첫 번째가 대표 방법 |
| `response` | 선택 직후 반응 줄들 |
| `set` | 기록에 병합할 값 |
| `flags` | 기록에 추가할 표식. 회복 후보는 `recovery:<선택ID>` 형식 |
| `next` | 다음 마디. 문자열이거나 조건 분기 배열 |
| `when` | 이 선택지를 **보여 줄 조건**. 회복 지점에서 진입 사유에 맞는 것만 띄울 때 쓴다 |
| `variants` | 직전 선택에 따라 `text`·`response`·`set`이 달라질 때. 배열 순서가 우선순위 |
| `post` | 선택 뒤 조건에 따라 자동으로 이어지는 줄들 |

### `variants`

`S1-02-C`처럼 같은 선택지인데 **요약하는 대상이 달라지는** 자리에 쓴다.

```json
"variants": [
  { "when": { "chose": ["S1-01-A", "S1-01-D"] },
    "text": "무대에서 좋은 기억 남기고 싶어서 …",
    "response": [ ... ] },
  { "when": { "chose": "S1-01-B" }, "text": "…", "response": [ ... ] }
]
```

첫 번째로 맞는 것 하나만 쓴다. `variants`에 없는 필드는 바깥 값을 그대로 쓴다.

### `post`

회복 지점의 '남은 표현 정정'처럼 **학생이 고르지 않았는데 자동으로 이어지는 말**이다.

**주의 — 원칙 4.** 자동으로 이어지는 '나'의 대사는 한 문장을 넘기지 않는다. 정정할 것이 둘이면 개별 문장을 잇지 말고 통합 문장 하나를 쓴다. `post`에 `oneOf`를 쓰는 이유가 이것이다.

---

## 5. 조건(`when`)

| 형태 | 뜻 |
| --- | --- |
| `{ "chose": "S1-01-D" }` | 그 선택지를 골랐다 |
| `{ "chose": ["A", "B"] }` | 둘 중 하나라도 골랐다 |
| `{ "notChose": "S1-01-A" }` | 고르지 않았다 |
| `{ "flag": "recovery" }` | 그 접두사로 시작하는 표식이 하나라도 있다 |
| `{ "is": ["stageMemory", "full"] }` | 기록 값이 같다 |
| `{ "relationship": "관계 악화" }` | S1~S4 미해결이 2개 이상이다. `대화 가능`은 0~1개다 |
| `{ "areaAtMost": ["empathy", 1] }` | 해당 영역의 적절한 선택이 기준 횟수 이하다 |
| `{ "all": [ ... ] }` | 전부 참 |
| `{ "any": [ ... ] }` | 하나라도 참 |
| `{ "not": { ... } }` | 거짓 |

조건을 새로 만들지 않는다. 표현이 부족하면 데이터를 나누는 쪽을 먼저 검토한다 — 조건이 복잡해질수록 대본과 대조하기 어려워진다.

## 6. 기록(state)

```js
{
  choices: ["S1-01-A", "S1-02-C", ...],   // 고른 순서대로
  lines:   { "S1-01-A": "왜 그 곡 …" },    // 화면에 나온 '나'의 대사 원문
  responses: { "S1-01-A": [...] },          // 그 선택 직후 실제로 나온 반응 줄
  flags:   ["recovery:S1-01-C"],
  record:  { stageMemory: "full", S1: "해결", 의상: "흰색안" },
  area:    { empathy: 3, mediation: 4 },
  history: [{ kind: "say", who: "해슬", text: "..." }], // 실제로 본 대사·지문
  checkpoints: { "S1-01": { ... } },       // 첫 플레이의 선택 직전 기록
  retry: null                               // 재도전 중 비교에 쓸 첫 기록
}
```

`area`는 `appropriate: true`인 선택을 고를 때만 올라간다. 부적절한 선택은 세지 않고, **적절한 회복 선택은 센다.**

재도전은 추천 지점의 `checkpoints`를 복원한 뒤 다른 선택을 기록한다. 중간 구간은 처음 선택을 다시 적용하고, 공연 당일은 다시 고르게 한다. 첫 기록은 `retry.originalState`에 보존해 마지막 비교 카드가 읽는다.

엔딩의 돌아보기 카드가 이 전부를 읽는다. 중간에 덮어쓰거나 비우지 않는다.

`src/storage.js`는 진행 상태를 장면 시작 지점마다 브라우저의 `localStorage`에 저장한다. 새로고침하면 저장된 장면의 처음부터 다시 보여 주며, 서버로 보내는 값이나 학생 개인 정보는 없다. 글자 크기는 진행 기록과 별도 키로 저장해 처음부터 다시 시작해도 유지한다.

---

## 7. 넣지 말아야 할 것

- 점수·호감도 같은 누적 수치. 관계는 **미해결 개수**로만 판정한다.
- 확률. 같은 선택은 언제나 같은 결과로 간다.
- 화면 표현(색·위치·애니메이션). 그것은 `ui.js`의 일이다.
- 교과서 방법 이름을 학생 화면 문구 안에 섞어 넣는 것. `method`는 해설용 메타데이터다.
